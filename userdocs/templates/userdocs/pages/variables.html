A variable is one value of a device. Its key is the name the device uses in its data, e.g. temperature in {"temperature": 25.1}.

Created automatically

When a device sends a key that does not exist yet, the variable is created automatically as a sensor with that key. You can then edit it to add a label and a unit. Add variables yourself when you want to choose the settings first, and always for actuators.

Settings of a variable

KeyLetters, digits and underscores, starting with a letter, at most 50 characters, e.g. soil_moisture. No spaces. Keys are case sensitive.
LabelDisplay name, e.g. "Soil moisture". Blank = the key is shown.
Unite.g. °C, %, V. May be blank.
KindSensor (read only) or Actuator (can be controlled from the platform).
Value typeNumber, On / off (stored as 1 and 0, shown as ON and OFF), or Categories (named states, see below).
CategoriesOnly for the value type Categories: one name per line, in order.
Minimum, maximumFor number actuators: the range a user may request, e.g. 0–180 for a servo. Blank = no limit.

Categories

Use the value type Categories for a value that is one of a few named states, such as a door that is closed, open or locked, or a mode that is auto, manual or off.

  • Enter the categories one per line, between 2 and 32, each at most 40 characters and not just a number.
  • Each category is stored as a number in the order of the list: the first is 0, the second 1, and so on. For closed / open / locked: closed = 0, open = 1, locked = 2.
  • Pages, charts, downloads, rules and messages show the names. A downloaded file has both the number and the name.
  • To add a category, add it at the end of the list. Renaming keeps the data. Changing the order changes the meaning of data already stored, and a list shorter than the highest number already used is refused.
WhereWhat happens with categories
Device sends dataThe name ({"door": "open"}, upper or lower case) or the number ({"door": 1}). An unknown name or a number outside the list is refused, with the list of allowed names in the error.
Actuator controlOne button per category (a drop-down list for more than four). The device receives the number, e.g. {"mode": 2}.
RulesChoose the category from a list in conditions (usually with = or ≠) and in Set actuator actions. In alarm and message texts, {value} is the name.
ChartsDrawn as steps with the category names on the vertical axis. When many readings are combined, a point shows the highest number in that period.

What a device may send

  • Values must be numbers. true and false are accepted and stored as 1 and 0. Text is accepted only for category variables, as the name of a category; other text values are rejected.
  • One message may contain many keys, and several readings with their own time (payload formats).
  • An actuator reports its real state with the same key, e.g. the pump sends {"pump": 1} after switching on.

Deleting a variable

Delete on the variable page removes the variable and all its data. If the device keeps sending that key, the variable is created again.
