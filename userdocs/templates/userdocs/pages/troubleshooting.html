The device does not connect

What you seeLikely cause and fix
Serial Monitor shows only dots after "Connecting to …"Wrong Wi-Fi name or password, or a 5 GHz-only network: the ESP32 supports 2.4 GHz only.
Strange characters in Serial MonitorSet the baud rate to 115200.
No port in Arduino IDEInstall the CP210x or CH340 USB driver and use a data cable.
HTTP status -1 or MQTT state -2The server cannot be reached: wrong address or port, a firewall on your network, or (with encryption) a wrong ROOT_CA (root certificate).
HTTP 401, MQTT state 5, CoAP 4.01Wrong access token, or the token was regenerated. Download the firmware template again with the device selected.
HTTP 403The device is inactive; activate it with Edit on the device page.
HTTP 301The server accepts https:// only. Change the address to https and fill in ROOT_CA.
HTTP 400The JSON is invalid or breaks a rule (text values, keys with spaces, time in seconds). The answer explains which; see payload.
MQTT connects but nothing is savedWrong topic prefix or token in the topic. Subscribe to the device's errors topic to see why messages are rejected.
A new device cannot log in to MQTTNew devices and new tokens are accepted by the broker after about 2 minutes.

Data and status

The device is shown offline although it worksIt is offline after {{ limits.offline_seconds }} seconds without data. Send data more often, or use MQTT with the status topic (Last Will).
A new key did not appearKeys must start with a letter and contain only letters, digits and underscores. Keys are case sensitive: Temp and temp are two variables.
The chart is emptyNo data in the chosen range. The page tells you when the latest reading was; choose a longer range.
Readings appear at the wrong timeThe device sent ts with a wrong clock. Leave ts out to use the time of arrival.

Controls and commands

An actuator stays on Waiting for deviceThe device is offline, uses HTTP (which cannot receive requests), or does not report the new state back with the same key.
MismatchThe device reported another value than requested: check the firmware and the hardware.
The LED of a template does not reactThe actuator variable is missing or has another key than the template (lamp for MQTT, pump for CoAP).
Commands expireThe device was offline, or its firmware does not handle commands. Choose a longer expiry.
Commands fail with "Unknown method"The firmware does not implement that method; the templates know blink and ping (and ota for MQTT).

Rules and notifications

A rule never activatesCheck that it is enabled, and look at Last evaluation on the rule page: a value shown as unknown is older than ignore values older than. With for at least, the condition must hold that long.
A rule switches on and off rapidlyAdd a clear when condition (hysteresis), a duration, or a cooldown (ECA rules).
A rule chain sends too many emailsPut a Rate limit or Value changed node before the email node.
An action fails with "no access"The rule's owner needs at least the Operator role on the target device.
A scheduled run was skippedThe execution log gives the reason: the condition was false or unknown, the rule was still active from the previous run, or the run could not start in time.
No Telegram messageConnect Telegram in My profile and use Send test. For groups and channels the bot must be a member or administrator.

Firmware updates

No version to choose under Update toNo uploaded firmware for this device's board, or the board is not set.
The update fails after Updating and the old version is backThe new firmware did not start: check it over USB first. Use a partition scheme with OTA support.
Stays Queued and then failsThe device was offline or does not run firmware that supports updates (the MQTT template does).
