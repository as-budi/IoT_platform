A device running the MQTT firmware template can be updated over the air (OTA): you upload a compiled firmware file once, then update any compatible device from its page. The device downloads the file, checks it, restarts into it and reports the new version.

A firmware is identified by its name and version, e.g. Greenhouse node 1.1.0. Devices with the same board can run different programs, so Pump controller 1.1.0 and Greenhouse node 1.1.0 are two different firmwares.

Preparing a device

  • Use the MQTT firmware template (or firmware that implements the same ota command) and upload it once over USB.
  • In Arduino IDE choose a partition scheme with OTA support, e.g. Default 4MB with spiffs.
  • Set the board of the device (device → Edit), or let the device report it.

Uploading firmware

  1. Set FW_TITLE to the name of your program, e.g. "Greenhouse node", and change FW_VERSION, e.g. from "1.0.0" to "1.1.0".
  2. Arduino IDE: Sketch → Export Compiled Binary. This creates a .bin file in the sketch folder.
  3. Firmware → Upload firmware: name as in FW_TITLE, version exactly as in FW_VERSION, board, the .bin file, and release notes if you like. Files up to {{ limits.firmware_max_mb }} MB are accepted; the platform computes the MD5 and SHA-256 checksums.

The name and version must match what the new firmware reports after it starts: that report is how the platform knows the update worked (capital letters in the name do not matter). A name + version can be uploaded only once per board; the same version under another name is accepted. Firmware you upload is visible only to you (administrators see all). The delete button at the end of each row removes a firmware and its .bin file. Updates that used it keep their history (name and version); an update that is still running with it is stopped as failed.

Updating a device

Device page → Firmware card → choose the firmware under Update to → Update firmware. Only firmware for the device's board is offered, except the one it runs now. The device must be online.

  • Another program (a different name) can be sent too, e.g. turning a Greenhouse node into a Pump controller. The platform asks you to confirm this first, because the device will do something else afterwards.
  • A device whose firmware does not report its name yet (no FW_TITLE) is compared by version only. Sending it firmware with the version it already runs also asks for confirmation: the platform cannot tell the new firmware from the old one, so a failed update may look successful.

Progress appears in the card by itself:

Queuedwaiting for the device to pick up the update command
Downloadingthe device downloads the file (with percentage)
Downloaded, Verifiedthe file is complete and its MD5 matches
Updatingthe device restarts into the new firmware
Updatedthe device started and reported the new name and version
Failedsee the reason in the update's details; the old firmware keeps running
Canceledyou clicked Cancel

Common reasons for Failed: the device was offline and did not pick up the command in time; the download broke or the checksum did not match; the new firmware did not start and the device went back to the old firmware (or FW_TITLE in the sketch differs from the name on the platform); or nothing was heard from the device for a long time. Starting and canceling updates needs the Editor role on a shared device. The Firmware page lists recent updates of all your devices.

The firmware report

Every template reports, when it starts (MQTT: on every connection), which firmware it runs and on which board:

MAC address

The report also carries the board's Wi-Fi MAC address. The platform stores it with the device and shows it in the Firmware card. It tells you which physical board is using the token, for example to find the board in your router's list of connected devices, or to notice that a token was copied to another board (the MAC address changes).

  • On the ESP32 the value comes from WiFi.macAddress(), after Wi-Fi has started.
  • Accepted forms: 24:6F:28:AA:BB:CC, 24-6f-28-aa-bb-cc, 246f.28aa.bbcc or 246F28AABBCC. It is stored as 24:6F:28:AA:BB:CC.
  • An invalid MAC address rejects the whole report, so nothing from it is saved.
  • Reports without mac are still accepted. The card then shows "unknown" until the device sends its MAC address.
