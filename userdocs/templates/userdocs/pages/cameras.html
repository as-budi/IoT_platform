An ESP32-CAM can send pictures (JPEG snapshots) to the platform: at a fixed interval, and whenever you press Capture now. Pictures appear on the device page and in a gallery, and are kept for a set number of days. Live video is not part of this version.

Setting up an ESP32-CAM

  1. Add a device and set its board to ESP32-CAM (device → Edit). The device page then shows the Camera card.
  2. Download the firmware template from Connect an ESP32 (MQTT, with the device selected): it contains your server, token and certificate.
  3. Arduino IDE: board AI Thinker ESP32-CAM, partition scheme Minimal SPIFFS (1.9MB APP with OTA). The ESP32-CAM has no USB port: use a USB-to-serial adapter (connect IO0 to GND while uploading). Power it with 5 V and at least 1 A.
  4. Optional actuators (add them as variables, kind "Actuator"): snapshot_interval (number, seconds, 0 = only on request), flash (on / off, the white LED is used while taking a picture), framesize (number, 5 = QVGA … 10 = UXGA, 8 = VGA by default) and quality (number, 10 = best … 63 = smallest).

The Camera card and the gallery

  • The card shows the latest picture (it changes by itself when a new one arrives) and the six most recent ones. Click a picture to open it full size.
  • Capture now (Operator and up) sends the command capture; the device takes a picture and uploads it at once. Rules can do the same with the action Send command, method capture.
  • All snapshots opens the gallery: newest first, page by page, with a day filter, download, and delete (Editor and up).
  • Snapshots older than {{ camera.retention_days }} days are deleted automatically every hour. In the gallery, Editors can set another number of days for this camera (0 = keep forever).
  • A picture also counts as data from the device: it updates Last data and the online status.

Uploading from your own firmware

Send the JPEG as the body of an HTTP POST:

POST {{ http.snapshot }}
Content-Type: image/jpeg
X-Source: periodic          (optional: periodic, command, device)
X-Command-Id: 42            (optional: the id of the capture command being answered)

<JPEG bytes>

Trying it from a computer:

curl -X POST {{ http.snapshot }} -H "Content-Type: image/jpeg" --data-binary @photo.jpg
StatusMeaning
201saved: {"id": 12, "size": 23456, "width": 640, "height": 480}
401 / 403unknown token / device inactive
413larger than {{ camera.max_kb }} KB
415not a JPEG image
429more than one picture every {{ camera.min_interval }} s (pictures answering a capture command are always accepted)

Pictures are not sent over MQTT: the broker accepts messages of at most 64 KB, and images are better kept out of it. MQTT carries the capture command and the settings.
