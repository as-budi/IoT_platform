There are two ways to make a device do something. Use a requested state for things that have a state (a relay, a fan, a servo, a set point) and a command for one-off actions (reboot, open a valve for 5 seconds).

Requested stateCommand
Examplespump ON/OFF, fan speed 60, servo 90°reboot, blink, open valve for N seconds
Device offlinethe request waits and is applied when the device comes backthe command expires if it is not picked up in time
Clicking several timesonly the latest value countsevery click is a new command
Proof it workedthe device reports the same valuestatus and response of the command

Switching an actuator

Actuator variables show a switch (on/off) or a number field with Set on the dashboard and the device page. The platform stores your request and passes it to the device; the device then reports its real state with the same key. The badge next to the actuator compares both:

Waiting for deviceThe device has not reported anything since the latest request (it may be offline).
In syncThe device reported the requested value.
MismatchThe device reported, but with another value (stuck, refused, or changed locally).

Number actuators only accept values within their minimum and maximum. Switching needs at least the Operator role on a shared device. How a device receives requested states is described in the MQTT and CoAP references. HTTP devices can only send data.

Sending a command

Device page → Commands:

  1. Method: the name of the action, e.g. reboot or blink. The device firmware decides which methods exist.
  2. Parameters: JSON for the action, e.g. {"times": 5}. Use {} for none.
  3. Expires after: 1 minute, 5 minutes, 1 hour or 1 day. A command that has not finished before it expires is never run later.

The table below the form shows each command with its status and the device's response:

Queuedwaiting for the device
Sentdelivered to the device, no answer yet
Succeededthe device answered with success
Failedthe device answered with an error, see the response
Expirednot finished in time; it will not run any more

Rules can also switch actuators and send commands automatically (Rules overview).
